If the form says “values must be in [0,1]”

The rejected file and server trace were not supplied, so its exact cause is unknown. Possible causes include negative values, values above 1, infinity, sentinel nodata or NaN inside the scored footprint. Do not assert that outside NaNs alone caused it: official format requires null/NaN outside.

Our writer rejects invalid in-footprint values, never silently clips, writes only NaN outside, and reopens the TIFF both as raw values and a masked raster. This closes those tested local defects; it is not a guarantee that an unauthenticated mirror matches a later organizer template.
